# 操作手册

## 完成第一次采集

1. 登录 FlowHarbor，进入节点页面，确认至少一个 Worker 在线。
2. 创建项目，例如“产品目录采集”。
3. 在任务管理中创建 Python 任务，例如“示例目录”，关联刚创建的项目。
4. 设置命令 `python main.py`，参数 `--url http://fixture/`，选择随机节点或指定一个在线 Worker。填写结果集合名称，例如 `catalog_demo`。
5. 上传 `examples/catalog/main.py`，保存路径使用 `main.py`。
6. 点击运行，进入执行记录并打开本次任务详情。
7. 等待状态完成；日志应显示采集到的商品，结果页应出现 3 条商品记录。

示例页部署在内部 `fixture` 服务，不映射宿主机端口。详见 [示例说明](../examples/README.md)。本地仅验证采集逻辑时，使用示例的 `--local` 参数。

## 定时计划

选择已有任务创建计划，填写五段 Cron：分钟、小时、日、月、星期。

| 表达式 | 执行时间 |
| --- | --- |
| `*/5 * * * *` | 每 5 分钟 |
| `0 * * * *` | 每小时整点 |
| `0 9 * * 1-5` | 工作日 09:00 |

默认部署时区为 `Asia/Shanghai`。启用后由 Crawlab Master 定时触发。暂停计划只阻止未来触发；已进入队列或正在运行的任务需在执行记录中单独取消。

计划保存自己的命令、参数和节点设置。修改采集任务的默认配置后，需要检查相关计划是否也需要同步修改。

## 执行状态

| 状态 | 含义 |
| --- | --- |
| pending | 已排队，等待节点执行 |
| running | 工作进程运行中 |
| finished | 进程完成 |
| error / abnormal | 失败或异常结束，查看错误和日志 |
| cancelled | 已取消 |

重新执行会创建新的执行记录。结果数量属于具体执行，不等于网页访问数。任务进程退出成功也不代表一定产生采集结果，应同时核对数据记录。

## 管理自己的脚本

脚本以 UTF-8 编码保存，上传单文件最大 1 MiB。需要依赖时，在部署镜像中安装固定版本的依赖并重新构建 Master/Worker；不要把本地虚拟环境上传。示例使用 SDK 的 `save_item` 保存结果，自定义脚本也需通过相同方式保存才能在结果页展示。

运行命令和参数由操作人员填写；选择多个节点会依据 Crawlab 的执行模式分发。首次验证建议指定单个 Worker，便于对应执行日志和结果。

删除任务、项目或计划前先核对其关联执行与计划。已保存的历史日志按 Crawlab 自身保留策略管理；本版本不额外承诺永久保存。
